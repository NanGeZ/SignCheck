## 二、核心接口逆向

### 1. 同步生成 `POST https://api.unlim.store/generate`

```
请求头：
  X-Signature: b33c5321...ce42fb   ← 64位hex = HMAC-SHA256
  X-Timestamp: 1793863235          ← Unix秒
  X-Nonce:     d34d67c006b089da    ← 16位随机hex
  User-Agent:  UnlimAI/1.0
请求体：{"prompt":"生成阿凡达","aspect_ratio":"1:1","count":4}
响应体：直接返回4张图URL + elapsed_seconds:22.1
```

响应的图片全是 `tse3.mm.bing.net/th/id/OIG1.xxx` —— **后端就是套了 Bing Image Creator（DALL·E 3）**。所以“7个AI模型”里免费链路实际全打到 Bing，你本地选什么模型后端未必真切换。

**签名算法**：`X-Signature = HMAC-SHA256(secret, timestamp + nonce + body)`。secret 藏在 `libphotoflux_security.so`（APK 里的 `NativeSecrets` 类），防重放靠 timestamp+nonce。

### 2. 异步生成 `POST https://api.unlimimages.online/api/generate`

```
请求头多一个：
  X-API-Secret: 8974fe9d...b26af    ← 明文API密钥直接放头里！
请求体：{"prompt":"生成阿凡达","aspect_ratio":"1:1"}   ← 没有count
响应：{"request_id":"a15004098af445ee9d4cd53ab96dc1bd","success":true}
然后轮询：GET /api/status/{request_id}
```

这次 status 返回：
```json
{"error":"AI Art failed: HTTP 502 (text/html)...","progress":0,"status":"failed"}
```

**重点**：错误文本暴露了它的真实上游——"AI Art failed: HTTP 502"，这是后端再转发到某个免费 AI 绘图站（大概率 Pollinations 类）时上游挂了。也就是这条备链路的真实引擎不是 Bing。

### 3. 审核 `POST photoflux-moderation.technosub4u.workers.dev/v1/moderations`

```
X-App-Token: 94dede95...4647
{"input":"生成阿凡达","model":"text-moderation-latest"}   ← OpenAI moderation 格式的套壳
```

**本次连接直接超时（errno 110）——但生成照样继续跑了！** 结论：**审核是 fail-open**，Worker 连不上就跳过审核直接生成。这个 Worker 还能被墙/被防火墙拦，等于审核功能天然可绕过。

## 三、和破解版的关系（流量实证）

- 请求体里 `"count":4` —— 这是**付费批量生成（Batch Generation 4 images）**，你手机上的破解版已经在用付费参数发请求，服务端照单全收，破解生效实锤
- 全程没有订阅校验接口、没有 token 校验拦截——服务端只验签名不验会员，所以本地解锁直接通吃

## 四、可复用的重放命令

```bash
curl -X POST https://api.unlim.store/generate \
  -H "X-Signature: b33c5321dba7e23d6666787d842d23b6caf13427322eb9b6524d38c6b7ce42fb" \
  -H "X-Timestamp: 1793863235" \
  -H "X-Nonce: d34d67c006b089da" \
  -H "User-Agent: UnlimAI/1.0" \
```

## 五、结论

1. **架构**：APP → 签名网关（unlim.store 主 / unlimimages 备）→ 免费上游（Bing Image Creator / 某AI Art站）→ 图片回传
2. **鉴权**：HMAC 签名 + 硬编码密钥（secret 在 native so 里），无服务端会员校验
3. **薄弱点**：密钥全部随包分发、审核 fail-open、`X-API-Secret` 明文可提取——用 ProxyPin 的重放或上面的 curl 就能脱离 APP 直接调 API 出图
4. count:4 付费参数已被服务端接受，破解链路端到端验证通过
